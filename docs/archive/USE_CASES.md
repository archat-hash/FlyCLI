# Вичерпні Сценарії Використання (Use Cases)

Цей документ містить деталізовані сценарії використання системи FlyCLI (100% покриття кодової бази). Сценарії покривають успішні шляхи виконання (Happy Paths), помилки (Edge Cases/Errors) та гілки (Branches).

---

## Epic 1: MSP Infrastructure & Base CLI

### UC-1: Сканування портів (`ListPortsUseCase.js`, `PortScanner.js`)
```gherkin
Функціонал: Пошук доступних Serial портів
  Сценарій: Успішне знаходження портів з підключеним контролером
    Припустимо система має доступ до бібліотеки SerialPort
    Коли користувач виконує "flycli scan"
    Тоді система викликає PortScanner
    І виводить список усіх доступних портів
    І позначає порти, чий 'manufacturer' або 'vendorId' відповідають відомим виробникам FC (STM32, CP210x)

  Сценарій: Відсутність доступних портів
    Припустимо до системи не підключено жодного USB-пристрою
    Коли користувач виконує "flycli scan"
    Тоді система виводить повідомлення "No serial ports found"
    І завершується з кодом 0
```

### UC-2: Перевірка здоров'я системи (`GetHealthCheckUseCase.js`)
```gherkin
Функціонал: Health Check системи
  Сценарій: Отримання статусу системи у форматі JSON
    Коли користувач виконує "flycli health"
    Тоді система генерує JSON об'єкт
    І об'єкт містить версію Node.js, стан SerialPort API, наявність папки .flycli
```

### UC-3: Базове виконання CLI команд (`ExecuteCliUseCase.js`, `MspProtocol.js`)
```gherkin
Функціонал: Виконання команди на Flight Controller
  Сценарій: Успішне виконання простої команди (наприклад, "status")
    Припустимо порт "/dev/ttyACM0" доступний
    Коли користувач виконує "flycli execute /dev/ttyACM0 115200 status"
    Тоді система відкриває порт
    І надсилає MSP-запит `API_VERSION` (MSP Handshake)
    І після отримання відповіді на handshake, надсилає текст команди "status\r"
    І читає буфер, поки не отримає символ запрошення "# "
    І повертає прочитаний текст (видаляючи echo самої команди)
    І закриває порт

  Сценарій: Помилка відкриття порту (Port Busy)
    Припустимо порт зайнятий іншим процесом (наприклад, Betaflight Configurator)
    Коли користувач виконує команду execute
    Тоді система перехоплює помилку "Access denied" або "Port busy"
    І генерує `ConnectionError`
    І виводить помилку в stderr (або як JSON, якщо активний прапорець --json)

  Сценарій: Таймаут під час MSP Handshake
    Припустимо пристрій підключено, але це не Flight Controller (не відповідає на MSP)
    Коли система надсилає `API_VERSION`
    І проходить більше 2000 мс без відповіді
    Тоді система генерує `TimeoutError`
    І закриває порт

  Сценарій: Отримання битого фрейму (MSP Checksum Error)
    Припустимо під час читання буфера від контролера контрольна сума MSP-фрейму не збігається
    Коли система парсить пакет
    Тоді вона генерує `DeviceError` з описом "Checksum mismatch"
```

## Epic 2: Interactive Human-in-the-Loop Wizards

### UC-4: Інтерактивне калібрування радіоапаратури (`rxCalibrationMachine.js`)
```gherkin
Функціонал: Калібрування RC через CLI
  Сценарій: Ідеальне калібрування всіх 4 осей
    Припустимо порт відкрито і встановлено режим поллінгу `MSP_RC` (кожні 50мс)
    Коли користувач переводить Roll, Pitch, Yaw та Throttle до крайніх значень (<1100 та >1900)
    Тоді кінцевий автомат (State Machine) фіксує успішне покриття діапазону для кожної осі
    І одразу після фіксації 4-ї осі генерує подію SUCCESS
    І виводить у stdout валідний JSON з результатами `channels`
    І візуальні індикатори прогресу виводяться виключно у `stderr`

  Сценарій: Таймаут бездіяльності (User Inactivity)
    Припустимо калібрування розпочато
    Коли стан осей не змінюється (відхилення < 50 одиниць) протягом 15 секунд
    Тоді кінцевий автомат переходить у стан TIMEOUT
    І зупиняє поллінг
    І виводить JSON зі статусом "timeout"
```

## Epic 3: AI Software Factory & Auditability

### UC-5: Збереження контексту дій агента (`AgentWorkflowService.js`, `AgentStorage.js`)
```gherkin
Функціонал: Логування CLI команд
  Сценарій: Прозоре перехоплення та збереження команди
    Припустимо агент запускає будь-яку команду flycli з прапорцем --json
    Коли команда завершує своє виконання
    Тоді `AgentWorkflowService` генерує `EventMessage` з деталями (stdout, stderr, exitCode)
    І додає його до файлу `~/.flycli/agent_logs/workflow_current.jsonl`

  Сценарій: Ротація логів
    Припустимо розмір поточного файлу `workflow_current.jsonl` досягає 1 МБ
    Коли система намагається записати нову подію
    Тоді файл перейменовується на `workflow_<timestamp>.jsonl`
    І створюється новий пустий файл для запису
```

### UC-6: Управління Event Bus Фабрики (`FactoryOrchestrator.js`, `MessengerService.js`)
```gherkin
Функціонал: Комунікація між агентами
  Сценарій: Ініціалізація нового Епіку
    Коли користувач виконує "flycli factory init epic-1"
    Тоді створюється новий стейт у `TicketState.js` зі статусом DRAFT
    І створюється файл `messenger_epic-1.jsonl`

  Сценарій: Відправка повідомлення агентом
    Припустимо епік "epic-1" ініційовано
    Коли агент виконує "flycli factory post epic-1 BA 'Готово'"
    Тоді повідомлення додається до JSONL файлу з таймстемпом та ідентифікатором ролі BA
```

## Epic 4: AI-Assisted CAD Integration

### UC-7: Ініціалізація та керування FreeCAD (`CadEngineProcess.js`, `McpCadTools.js`)
```gherkin
Функціонал: MCP Інтеграція FreeCAD
  Сценарій: Lazy-старт процесу
    Припустимо сервер MCP запущено через "flycli factory mcp_cad_command"
    Коли жоден клієнт не надсилає запитів
    Тоді процес FreeCAD у системі не існує (не споживає RAM)

  Сценарій: Виконання CAD-команди та пробудження
    Припустимо клієнт надсилає запит "create_cube" через MCP
    Коли `CadEngineProcess` визначає, що процес мертвий
    Тоді він запускає `FreeCADCmd` як дочірній процес
    І чекає його готовності через stdout
    І передає Python-скрипт для виконання
    І повертає результат через MCP

  Сценарій: Відсутність FreeCAD у системі
    Припустимо змінна FREECAD_PATH вказує на неіснуючий файл
    Коли відбувається спроба запуску дочірнього процесу
    Тоді `EnvironmentManager` кидає помилку "FreeCAD executable not found"
    І MCP сервер повертає помилку клієнту
```
